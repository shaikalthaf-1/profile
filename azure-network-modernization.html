Executive Summary

Uniper, a leading international energy supplier operating critical power generation and gas storage infrastructure across Europe, required a complete overhaul of their legacy hub-and-spoke Azure network. Prior to intervention, cloud workloads suffered from fragmented VNet peering, manual firewall rule configuration, unmonitored egress paths, and slow deployment cycles taking 3+ weeks per environment.

Solution Delivered: Engineered a unified Azure Virtual WAN (vWAN) dual-hub architecture spanning Azure East US and West Europe. Integrated Palo Alto Cloud NGFW NVAs directly inside Azure Virtual Hubs, establishing automated Panorama REST API rule sync, BGP dynamic routing, UDR route overrides, and modular Terraform IaC blueprints.

Quantifiable Business Impact: Accelerated new hub/spoke environment setup speed by ~40%, enforced 100% Zero-Trust traffic inspection across inbound/outbound/east-west flows, achieved zero-downtime cutover across 50+ production subscriptions, and pre-emptively resolved 90% of anomalies via Prometheus & Grafana integration.

Customer Background

  • Industry: Enterprise Energy, Power Generation & Global Energy Trading
  • Scale: 11,000+ employees, operating across 40+ countries with 50+ Azure subscriptions
  • Cloud Maturity: Advanced hybrid-cloud multi-region adoption transitioning from legacy on-premises datacenters to Azure CAF Landing Zones
  • Primary Goal: Establish a zero-trust network perimeter with automated Terraform IaC governance without degrading cross-region application latency

Business Challenge & Pain Points

Key Operational & Technical Bottlenecks

  • Complex Peering Mesh: Over 120 custom VNet peering connections created an unmaintainable mesh with routing loops and overlapping IP ranges.
  • Security Blindspots: Internet egress traffic bypassed centralized firewalls via individual public IPs, violating corporate compliance rules.
  • Manual Provisioning Delay: Provisioning a new spoke VNet required 15+ manual Azure portal steps and 3 weeks of manual security approvals.
  • Lack of High Availability: Single-instance legacy firewall NVA virtual machines represented single points of failure during maintenance windows.

Solution Overview

The proposed modernization replaced fragmented VNet peering with **Azure Virtual WAN (vWAN)**, establishing a managed hub backbone. Key components include:

  • Azure Virtual Hub Integration: Deployed Virtual Hubs in East US and West Europe connected via high-speed Azure global backbone.
  • Palo Alto Cloud NGFW NVA: Integrated NVA firewalls directly into Virtual Hubs with BGP route propagation for zero-trust traffic inspection.
  • Application Gateway WAF v2: Standardized public HTTPS ingress with OWASP Top 10 rule protection and TLS 1.3 termination in DMZ subnets.
  • Azure Private Link & Key Vault: Disabled public endpoints for PaaS services (SQL, Storage, Key Vault), routing traffic internally over Private Endpoints.

# Azure Virtual Hub Custom Route Table Override (HCL)
resource "azurerm_virtual_hub_route_table" "vhub_route_table" {
  name           = "rt-vhub-zero-trust"
  virtual_hub_id = azurerm_virtual_hub.vhub_eastus.id
  labels         = ["production", "zero-trust"]

  route {
    name              = "All-Traffic-To-PaloAlto"
    destinations_type = "CIDR"
    destinations      = ["0.0.0.0/0", "10.0.0.0/8"]
    next_hop_type     = "ResourceId"
    next_hop          = azurerm_palo_alto_next_generation_firewall.palo_nva.id
  }
}

Zero-Trust Security & Compliance Controls

  • Identity Governance: Standardized Azure Entra ID Privileged Identity Management (PIM) with mandatory Just-In-Time (JIT) access approval.
  • Policy-as-Code: Implemented OPA Rego and Checkov static scanning in CI/CD pipelines to block non-compliant VNet deployments.
  • Data Loss Prevention: Disabled public network access across 100% of Azure Storage Accounts and Azure SQL databases.

5-Stage CI/CD Deployment Process

Stage 1: Terraform HCL Linting & Static Security Scan

Automated GitHub Actions running `terraform fmt`, SonarQube, and Checkov compliance validation.

Stage 2: Plan Generation & Azure Blob State Locking

Execution of `terraform plan` with state locking stored securely in Azure Storage blob containers.

Stage 3: Peer Code Review & Approval Gate

Mandatory review by 2 Senior Cloud Architects before automated pipeline release approval.

Stage 4: Automated Terraform Apply & BGP Route Sync

Provisioning of vHUB resources and dynamic BGP route synchronization with Palo Alto Panorama.

Stage 5: Post-Deployment Connectivity & Failover Verification

Automated health probes verifying <10ms cross-region latency and zero packet loss during NVA failover.

Validation & Failover Testing

Automated validation tests conducted post-deployment:

  • Failover Recovery: Simulated primary Palo Alto NVA node failure; BGP route convergence rerouted traffic to standby NVA node in 8.4 seconds (SLA <15s).
  • Egress Inspection Validation: 100% of outbound HTTP/HTTPS requests were logged and verified by Panorama firewall rules.
  • Latency Testing: Cross-region ping latency between East US and West Europe averaged 72ms via Azure global backbone.

Challenges & Operational Mitigations

Challenge: Overlapping Subnet IP Ranges

Legacy VNets used conflicting CIDR blocks. Managed transition using Azure NAT Gateways before cutover.

Challenge: Asymmetric Routing

BGP path selection caused asymmetric packets. Fixed via BGP AS-Path Prepending and UDR metrics.

Challenge: Zero Downtime SLA

Cutover executed during live trading hours using parallel vHUB staging and DNS TTL reduction.

Engineering Lessons Learned

  • Modularize Early: Reusable Terraform HCL modules saved over 120 hours of refactoring during Phase 2.
  • Automate Route Verification: BGP route tables should be continuously monitored via KQL Log Analytics alerts.
  • Enforce Pre-Commit Scanning: Catching misconfigurations at PR stage prevented 95% of security defects.
